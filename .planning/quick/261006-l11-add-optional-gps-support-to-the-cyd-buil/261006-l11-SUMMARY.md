# Phase quick-261006-l11 Plan 01: Optional GPS on the CYD Summary

The cyd-gps and cyd-ili9341-gps builds read an ATGM336H on GPIO35. A fresh fix puts the latitude, longitude and accuracy at the end of each SD row, sets a clock that has no network time, and shows on the main screen, DIAGNOSTICS and the alert card. On every board with a card, SD rows now start with the UTC time and go to one file per local day.

## Checks for the user tonight, with no module

1. In the emulator GUI (`cd sim && SQUACHSIM_NMEA=gps_sample.nmea python3 gui.py`), watch the Live tab. There is no GPS label for the first second. A dim label shows while the sample searches (about 20 s), then a green label once it fixes, and the corner clock is set. The label goes dim again about 5 s after the file ends. DIAGNOSTICS shows the satellite counts climb and then the fix.
2. Flash cyd-gps on a real CYD with no module. DIAGNOSTICS reads "GPS: no data on GPIO35" and the top bar shows no GPS label.
3. On the serial console at 2,000,000 baud, type `GPS FAKE -33.857 151.215`, then `GPS STATUS`. The status line shows the position with "(fake)". The top bar shows an amber GPS label, DIAGNOSTICS shows FAKE, and the clock does not change.
4. With an SD card in, trigger a detection. The alert card shows the coordinates with FAKE. The file is squachwatch-YYYYMMDD.log (or squachwatch-nodate.log with no trusted clock), and the row ends with the position and FAKE.

## Decisions stated for the record

- The GPS envs have no web flasher manifest and no release or CI job until a test on hardware.
- The browser emulator has no GPS.
- Non-GPS builds keep the seven-column row.
- Rows written against a bench fix carry the position, with FAKE in the accuracy column.
- No test of the SD file name was written. It is gmtime_r plus snprintf, and its time-zone part lives in Clock::localDay, which the host test cannot reach without the clock shims. A wrong name shows on the first card read.

## Deviations from Plan

### Auto-fixed Issues

1. [Rule 3 - Blocking] Renamed `SdRow::degrees` to `SdRow::degreesText` and `LINE_MAX` to `ROW_MAX`. Arduino defines a `degrees()` macro and POSIX `<limits.h>` defines `LINE_MAX`, so the board build failed with the plan's names. Files: include/sd_row.h, src/sd_row.cpp, src/sd_log.cpp, test/sd_row_test.cpp. Commit 16fbe67.
2. [Rule 3 - Blocking] Added `src/sd_row.cpp` to the emulator's UI_SRCS along with gnss.cpp in Task 2. The GPS STATUS line in main.cpp prints positions with SdRow::degreesText, so squachsim-live needed it to link. Commit b71e504.
3. [Rule 1 - Bug] SdLog::tick() also reopens the file when `_filename` is empty. wipe() clears it with a comment saying the next event reopens the file, but nothing did that before. Commit 16fbe67.
4. On a GPS build the WATCH pill's right limit is set from the GPS label's left edge (the same variable the watch's corner clock uses), so the pill cannot run under the label. Commit 008db75.
5. The dim label color is Theme::W95_SHADOW, the dimmest gray in theme.h. There is no Theme::DIM.
6. GPS OFF on the CYD (command 2) prints a short line after Gnss::reset(). The plan named the reset only.

### Tests dropped or not written

None of the plan's test cases were dropped. The plan's own exclusion (no file-name test) stands, with the reason above.
