# Quick Task 261006-l11: Optional GPS on the CYD - Context

**Gathered:** 2026-10-06
**Status:** Ready for planning

<domain>
## Task Boundary

Add optional GPS support to the 2.8" CYD (ESP32-2432S028R). A person with a GPS module plugged in gets the position of each detection in the SD card log, a correct clock without WiFi, and can see whether the GPS has a fix.

Hardware: an ATGM336H NMEA module (GPS + BeiDou, 9600 baud, 3.3V). GPS TX goes to GPIO35 on the P3 connector. Power comes from 3.3V and GND on CN1. GPS RX is not connected, so the firmware cannot configure the module.

Also in scope:
- Fix the SD detection log. The ts column is millis since boot, and file names count days since boot, so every session appends to squachwatch-0.log. Use wall-clock time and date-based file names when the clock is set.
- Correct the stale "Unused GPIOs" list in docs/PINOUT.md. GPIO 4, 16, 17 drive the status light; 12 and 13 are the display bus; 26 is the speaker; 34 is the light sensor; 37 and 38 are not on the connectors. GPIO 21 and 27 are driven at boot (backlight). The spare pins are 22 and 35 (and 27 on CN1, which is driven high at boot).

</domain>

<decisions>
## Implementation Decisions

### How GPS is switched on
- A separate build, behind a build flag (for example `-DCYD_GPS=1`). Boards without the flag compile none of the GPS path and their RAM use does not change.
- Add new PlatformIO environments derived from the existing CYD ones with `${env:...build_flags}` inheritance.

### What goes on the SD card
- Add position columns to the END of each detection CSV row: latitude, longitude, horizontal accuracy. Empty fields when there is no fresh fix. Existing columns keep their order.
- On builds without GPS the row format is unchanged, or gains the same empty columns; planner decides, and states which.
- No wigle.net wardriving file in this task. It needs a RAM measurement on hardware first (the CYD has no PSRAM, and the watch's wardrive store lives in raw flash the CYD does not have).

### Where fix status shows
- Main screen: a small GPS indicator in the top bar. Dim while searching, lit with a fresh fix. Not drawn on non-GPS builds.
- Diagnostics page: satellites in view, heard and used; accuracy; position; age of the last fix; and free heap / largest block so the RAM cost can be measured with and without the module.
- Alert card: the coordinates where the detection happened, when there was a fresh fix at detection time.
- Not desk mode.

### Clock
- A GPS fix with a date (RMC) sets the wall clock when the clock has no NTP time yet. NTP stays the preferred source when it is available. Use the existing Clock API; do not add a second time source path.

### Testing before the module arrives (added 2026-10-06)
- The module arrives on 2026-10-07. The work must be exercisable without it.
- PC emulator: a HardwareSerial shim in sim/ fed from an NMEA file (env var), so squachsim-live runs the same serial read loop as the board. A sample NMEA file with a no-fix period, then a fix with a date.
- Real CYD: the serial console commands GPS FAKE and GPS STATUS work on the CYD GPS build. A faked fix is marked as fake, as on the watch.

### Claude's Discretion
- Which CYD envs get a GPS twin (at least `cyd`; `cyd-ili9341` and the `-fast` variants are the same board with a different display driver or SPI speed).
- Web flasher manifests and release workflow jobs for the new envs: leave out until the build is tested on hardware, and say so in the summary.
- Serial port choice: Serial2 (UART2) with RX=35, TX=-1, 9600 baud.
- Whether the detection record carries the position, or the SD writer and alert card read Gnss::fix() at the moment of detection.

</decisions>

<specifics>
## Specific Ideas

- Reuse `src/gnss.cpp` (board-independent NMEA parser, already host-tested in `test/gnss_test.cpp`). Today only the T-Watch S3 path in `src/main.cpp` drives it (`gpsStart`, `gpsTick`, `Serial1`, power control through the PMU). The CYD path has no power control.
- Measured on 2026-10-06 with `pio run -e cyd`: static RAM 94,208 bytes (28.7%); firmware 1,740,465 of 1,966,080 bytes (88.5%). The parser object is 156 bytes of RAM and 2.6 KB of code. Runtime free heap on real boards is 14-39 KB with a largest block of 5-27 KB, so keep heap use small and fixed. No new large buffers.
- RAM budget notes are in comments in `src/detection.cpp` (scan flush at an 8 KB largest block), `src/sd_log.cpp` (SD_MAX_FILES = 2) and `src/main.cpp` (77 KB frame buffer).

</specifics>
