<name>Task 1: Baseline sizes, the shared capture header, and the CYD repeat table with its host test</name>
<files>include/wardrive_capture.h, src/wardrive_seen.cpp, src/wardrive.cpp, test/wardrive_seen_test.cpp, test/Makefile</files>
<behavior>
The test answers one plain question: without it, a driver parked beside a cafe could upload hundreds of copies of the cafe's network, or a board that has passed 256 devices could stop recording anything new.
- A network heard ten times from one spot within 5 minutes: the first hearing is worth writing, the next nine are not.
- The same network from about 67 m away: worth writing again.
- The same network 301 s after its last row, from the same spot: worth writing again.
- The same address heard over Bluetooth and over WiFi: two separate entries.
- A fresh table filled with 256 different devices: all 256 are worth writing, and hearing all 256 again at once from the same spot writes none of them (the table holds 256).
- A 257th device: worth writing, and it replaces the entry written longest ago. The second-oldest device heard again is still not worth writing. The oldest device heard again is worth writing, because it was the one replaced.
</behavior>

Switch (decision 2): the watch's Preferences namespace "wardrive" and key "on", default off. sdBegin() reads it; setEnabled() stores it. Use a function-local or begin-time Preferences, the same calls the watch uses.

Buffers (decision 6): six heap allocations, made in sdTick() on the loop task only while the switch is on and a card is mounted: the WiFi Q, the BLE Q (1,442 bytes each), the four SeenTable blocks (1,280 bytes each, zeroed) and a 1,024-byte row buffer. Safe freeing against the radio tasks: a `volatile bool s_live` that is set true with `__atomic_store_n(..., __ATOMIC_SEQ_CST)` only after all six pointers are set, and an `int s_users` counter. noteWifi and noteBle: return at once if s_live is false or s_paused is true (count a paused sighting as dropped). The free path stores s_live false (seq_cst), waits while `__atomic_load_n(&s_users)` is not 0 (a bounded loop with `delay(0)`; producers hold it for microseconds), then deletes.
